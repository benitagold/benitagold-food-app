# برنامه غذایی روزانه بنیتاگلد

وب‌اپلیکیشن ثبت تعداد غذای روزانه گالری و دفتر بنیتاگلد، با ارسال خودکار پیامک به هماهنگ‌کننده.

## اجرای پروژه

```bash
npm install
cp .env.example .env.local   # سپس مقادیر واقعی FarazSMS را در آن بنویسید
npm run dev
```

سپس آدرس `http://localhost:3000` را باز کنید.

برای build نهایی:

```bash
npm run build
npm run start
```

## ساختار پروژه

```
app/
  page.tsx                  فرم اصلی (client component)
  layout.tsx                چیدمان کلی، فونت، RTL
  globals.css                استایل‌های عمومی
  api/submit-meal/route.ts  API route: اعتبارسنجی + بررسی بازه زمانی + ارسال پیامک
lib/
  time-window.ts            منطق «باز/بسته» بودن سیستم (Asia/Tehran)
  sms.ts                    اتصال به سرویس FarazSMS
  rate-limit.ts             جلوگیری از ثبت تکراری
```

## تکمیل اتصال به سرویس پیامک (مرحله نهایی)

فایل `lib/sms.ts` را باز کنید و تابع `buildRequest` را با مستندات دقیق پنل
FarazSMS خودتان تطبیق دهید. سه حالت رایج در کامنت‌های همان فایل توضیح داده
شده‌اند (JSON با username/password، JSON با apikey، یا query string). پیاده‌سازی
فعلی حالت اول را فرض کرده است.

مقادیر زیر را در `.env.local` (نه در کد!) قرار دهید:

```
FARAZSMS_USERNAME=...
FARAZSMS_PASSWORD=...
FARAZSMS_SENDER_NUMBER=...
```

شماره گیرنده پیامک (`09131885395`) داخل `app/api/submit-meal/route.ts` به‌صورت
ثابت تعریف شده؛ در صورت نیاز به تغییر آن هم می‌توانید مقدارش را env variable کنید.

## نکات امنیتی رعایت‌شده

- کلیدهای FarazSMS فقط در سمت سرور (API route) خوانده می‌شوند و هرگز به مرورگر ارسال نمی‌شوند.
- بازه زمانی (شنبه–چهارشنبه، ۱۲–۱۵) هم در کلاینت (برای UX) و هم دوباره در سرور
  (`app/api/submit-meal/route.ts`) بررسی می‌شود — کلاینت هرگز منبع مورد اعتماد نیست.
- ورودی‌ها در سرور اعتبارسنجی می‌شوند (عدد صحیح مثبت، سقف منطقی).
- یک idempotency key تولیدشده در کلاینت + یک محدودیت زمانی کوتاه (cooldown) در
  سرور از ثبت تکراری/دوبار کلیک جلوگیری می‌کند (`lib/rate-limit.ts`).

## توسعه بیشتر پیشنهادی

- اگر تعداد سفارش‌ها باید تاریخچه/گزارش‌گیری داشته باشد، یک دیتابیس سبک
  (مثلاً SQLite یا Postgres) اضافه کنید و هر ثبت را قبل/بعد از ارسال پیامک ذخیره کنید.
- برای مقیاس چند-نمونه‌ای (چند سرور instance)، `rate-limit.ts` را با یک store
  مشترک (مثلاً Redis) جایگزین کنید.
